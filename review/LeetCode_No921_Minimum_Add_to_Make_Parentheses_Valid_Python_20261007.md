# LeetCode No.921 Minimum Add to Make Parentheses Valid Code Review

## 풀이 요약

현재 풀이는 스택에 아직 짝을 찾지 못한 괄호를 저장합니다. `(`는 스택에 추가하고, `)`를 만났을 때 스택의 마지막 값이 `(`라면 두 괄호를 짝지어 제거합니다. 짝을 찾지 못한 닫는 괄호도 스택에 남깁니다. 순회가 끝난 뒤 남은 괄호마다 반대 방향의 괄호 하나를 추가하면 문자열을 유효하게 만들 수 있으므로, 남은 스택의 길이를 반환합니다.

## 정확성

알고리즘은 올바릅니다. 괄호 문자열에서 이미 처리한 접두 구간의 괄호 쌍은 즉시 제거되고, 스택에는 짝을 찾지 못한 괄호만 남습니다. 각 남은 `(`에는 뒤에 `)` 하나를, 각 남은 `)`에는 앞에 `(` 하나를 추가해야 합니다. 따라서 최종 스택 길이가 필요한 최소 삽입 횟수입니다.

## 복잡도

- 시간: **O(n)** — 문자열을 한 번 순회합니다.
- 공간: **O(n)** — 최악에는 입력의 괄호를 모두 스택에 저장합니다.

시간 복잡도는 최적입니다. 이 문제는 스택 없이 카운터만 사용해 공간을 **O(1)**로 줄일 수 있습니다.

## 개선 제안

`unmatched_open`은 짝을 기다리는 여는 괄호 수를 유지합니다. 짝이 없는 `)`를 만나면 필요한 삽입 횟수를 늘립니다. 마지막에 남은 여는 괄호마다 닫는 괄호 하나가 필요하므로 두 값을 더해 반환합니다.

```python
class Solution:
    def minAddToMakeValid(self, s: str) -> int:
        unmatched_open = 0
        insertions = 0

        for char in s:
            if char == "(":
                unmatched_open += 1
            elif unmatched_open > 0:
                unmatched_open -= 1
            else:
                insertions += 1

        return insertions + unmatched_open
```

이 개선 풀이도 시간 **O(n)**, 공간 **O(1)**입니다.

## 세부 피드백

- 현재 코드의 `letter`는 한 글자이므로 `char`가 더 익숙하고 간결한 이름입니다.
- 입력이 `(`와 `)`만으로 구성된다는 문제 조건에서는 `else`로 닫는 괄호를 처리해도 괜찮습니다. 다른 문자가 입력될 수 있는 환경이라면 `elif char == ")"`로 조건을 명시하는 편이 안전합니다.
- 현재 메서드는 입력 타입을 `s: str`로 표시했습니다. 반환 타입도 `-> int`로 표기하면 의도가 더 분명해집니다.

## 종합

현재 풀이는 정확하고 선형 시간에 동작합니다. 스택을 이용한 접근도 이해하기 쉽지만, 이 문제에서는 카운터 풀이로 추가 공간을 상수 크기로 줄일 수 있습니다.
