# LeetCode No.39 Combination Sum Code Review

# LeetCode 39 — Combination Sum 코드 리뷰

## 총평

현재 풀이는 **후보 숫자를 재사용하면서 중복 조합을 피하는 백트래킹**입니다. LeetCode의 입력 조건(후보가 서로 다른 양의 정수)을 만족한다면 정답을 올바르게 찾습니다. 다만 매 재귀 호출에서 경로 리스트를 복사하고, 후보를 정렬하지 않아 가능한 가지를 일찍 잘라내지 못합니다.

## 1. 시간 복잡도

`D = target // min(candidates)`라고 하면, 한 경로에 선택할 수 있는 최대 숫자 개수는 `D`입니다. 각 깊이에서 후보를 순회하므로, 느슨한 최악의 상한은 **O(n^(D+1) · D)**입니다. 여기서 `n`은 후보 수입니다. 실제 실행 시간은 탐색 트리의 크기와 반환되는 조합 수에 좌우됩니다.

또한 각 분기에서 다음과 같이 경로를 복사합니다.

```python
newCurrent = [x for x in current]
```

복사 비용은 현재 깊이에 비례하므로, 탐색 노드가 많을수록 추가 비용이 발생합니다. 결과를 만드는 데 드는 비용도 별도로 고려해야 합니다. 반환되는 조합이 `C`개라면 결과 저장 공간과 복사 비용은 대략 **O(C · D)**입니다.

**최적화 여지:** 후보를 오름차순 정렬하면 현재 후보가 남은 목표보다 커지는 순간 반복을 중단할 수 있어 불필요한 탐색을 줄일 수 있습니다.

## 2. 공간 복잡도

- 재귀 깊이: 최대 **O(D)**
- 재귀 경로 복사로 사용하는 보조 공간: 재귀 스택에 서로 다른 경로 리스트가 유지되어 최악에는 **O(D²)**
- 결과 저장 공간: **O(C · D)**

경로를 하나만 유지하며 추가/제거하는 방식으로 바꾸면 보조 공간을 **O(D)**까지 줄일 수 있습니다. 결과 저장 공간은 반환해야 하는 조합 때문에 여전히 필요합니다.

## 3. 문제에 적합한 정석 접근

이 문제는 **백트래킹(DFS)**이 일반적인 정석 풀이입니다. 각 후보를 선택하거나 건너뛰는 탐색을 수행하되, 시작 인덱스를 다음 재귀 호출에도 넘겨 같은 후보의 재사용을 허용하고 조합 순서를 고정해 중복을 피합니다.

DP로 풀 수도 있지만, 문제에서 모든 조합을 반환해야 하므로 조합을 직접 열거하는 백트래킹이 더 자연스럽습니다.

## 4. 현재 풀이의 적절성과 개선점

`currentIndex > index` 조건은 현재 인덱스보다 앞선 후보를 건너뛰게 합니다. 따라서 후보를 다시 사용할 수 있고, 같은 조합을 다른 순서로 중복 생성하지 않습니다. 후보가 정렬되지 않았더라도 인덱스 순서 기준으로 조합을 한 번씩 생성하므로 **정답성에는 문제가 없습니다**.

개선할 부분은 다음과 같습니다.

- **정렬 및 가지치기:** 후보를 정렬한 뒤 `candidate > remaining`이면 반복을 종료할 수 있습니다.
- **남은 목표 전달:** `currentSum` 대신 남은 목표를 재귀 인자로 전달하면 합계를 매번 다시 관리할 필요가 없습니다.
- **경로 리스트 재사용:** 매 호출마다 복사하는 대신 `append` 후 재귀 호출하고, 돌아온 뒤 `pop`하는 전형적인 백트래킹 패턴을 사용할 수 있습니다.
- **명확한 변수명과 타입:** 내부 함수 매개변수에도 타입을 지정하고 `currentSum`을 `remaining`처럼 표현하면 의도가 더 분명합니다.

LeetCode의 조건에서는 후보가 양의 정수이므로 합이 목표를 초과했을 때 탐색을 종료하는 처리가 유효합니다. 후보에 `0`이나 음수가 허용된다면 종료 조건과 종료 가능성 자체를 다시 검토해야 합니다. 또 후보가 중복된 입력을 받으면 같은 조합이 중복 반환될 수 있지만, LeetCode 39의 입력 조건은 후보가 서로 다릅니다.

## 5. Python 관용성 및 예외 사항

`result.append(current)`는 여기서는 안전합니다. 이후 경로를 직접 수정하지 않고 매 분기마다 새 리스트를 만들기 때문입니다. 다만 매번 경로를 복사하는 방식보다 `append`/`pop` 방식이 메모리와 실행 효율 면에서 더 일반적입니다.

또한 괄호는 불필요하므로 다음처럼 간결하게 쓸 수 있습니다.

```python
for index, candidate in enumerate(candidates):
```

`target == 0`이면 현재 코드는 빈 조합 `[[]]`을 반환합니다. 문제의 일반적인 제약에서는 목표가 양수라 해당 상황이 없지만, 별도 API로 사용한다면 원하는 동작인지 확인할 필요가 있습니다.
